## Verdict

Ship Turnstile as a small surface on **`@lunora/auth`** (its primary value is sign-up/login bot protection) rather than a standalone package, but keep the core `verifyTurnstile()` helper transport-agnostic so it is also usable from any mutation/action. The standalone helper is a pure function: POST `secret` + `token` (+ optional `remoteip`) to the siteverify endpoint and return the parsed `{ success, errorCodes, ... }`. The procedure-guard integration follows the **`@lunora/ratelimit` middleware precedent** exactly — `rateLimit(...)` in `packages/ratelimit/src/middleware.ts:57-98` is a `Middleware<Context, Context>` that runs a check and throws a structural `LunoraError` (`{ name: "LunoraError", code, status }`) on failure, which the runtime maps to an HTTP/RPC status without importing `@lunora/server`. `verifyTurnstileMiddleware()` mirrors this: pull the token from `ctx` (or args), verify, throw `FORBIDDEN`/403 on failure. For the **auth** seam, Turnstile verification belongs in the host's `handleAuthRequest` wrapper (`packages/auth/src/handler.ts:17-31`): a thin `withTurnstile(handler, options)` that intercepts attempt routes (`/sign-up`, `/sign-in`) before `auth.handler(request)` runs and rejects when the token fails — the same place the runtime already classifies auth ATTEMPT routes (`packages/runtime/src/create-worker.ts:824` `AUTH_ATTEMPT_SEGMENTS`).

## Current state

- **No Turnstile anywhere.** No siteverify call, no CAPTCHA helper, no binding. `grep -ri turnstile packages/` is empty.
- **Auth handler seam**: `packages/auth/src/handler.ts:17-31` — `handleAuthRequest(auth, request, basePath)` prefix-matches `/api/auth/*` and delegates to `auth.handler(request)`. This is the single choke point where every sign-in/sign-up/callback flows through, so a Turnstile pre-check wraps here. The host calls it directly (e.g. `apps/playground/src/server/index.ts:2` imports `handleAuthRequest`), and the runtime can also pre-bind it via `WorkerOptions.authHandler` (`packages/runtime/src/create-worker.ts:468`).
- **Auth ATTEMPT classification already exists**: `packages/runtime/src/create-worker.ts:819-843` defines `AUTH_ATTEMPT_SEGMENTS = ["/sign-in", "/sign-up", "/callback"]` and `isAuthAttemptPath()` — Turnstile should gate the same `/sign-up`/`/sign-in` segments (not `/callback`, not reads), so reuse this segment set conceptually (inline a small copy in `@lunora/auth` rather than importing `@lunora/runtime`, matching how `@lunora/auth` already inlines `DEFAULT_AUTH_BASE_PATH` — `packages/auth/src/handler.ts:7`).
- **Middleware precedent (`@lunora/ratelimit`)**: `packages/ratelimit/src/middleware.ts:57-98` is the template for a procedure guard — it's a `Middleware<Context, Context>` (type-only `@lunora/server` import, line 1), runs a check, and on rejection throws `Object.assign(new Error(...), { name: "LunoraError", code, status })` so the runtime maps it. The "fail closed by default" posture (lines 43-56, `failOpen?`) is exactly the right default for a CAPTCHA guard. `verifyTurnstileMiddleware` should copy this structure (including the `Middleware<Context, Context>` type-only import) so it stays free of a runtime `@lunora/server` dep.
- **Auth context surface**: `packages/auth/src/middleware.ts:159-213` shows the established pattern for an auth-side middleware (`withAuthPlugins` → `LunoraAuthApiContext`), and notes that the **procedure context carries only the resolved identity, not the raw `Headers`** (lines 244-249). Consequence: a Turnstile _procedure_ middleware must read the token from the function `args` (not request headers), whereas the _auth-handler_ wrapper has the real `Request` and can read `cf-turnstile-response` from the form body / a header.
- **Auth exports**: `packages/auth/src/index.ts:1-32` is the barrel the new standalone symbols (`verifyTurnstile`, `verifyTurnstileMiddleware`, types) get added to. **Correction (discovered during implementation):** better-auth **does** ship a first-party `captcha` plugin covering Cloudflare Turnstile — so the auth-flow guard is _not_ Lunora-native; we re-export better-auth's `captcha` from `@lunora/auth/plugins` instead of hand-rolling a wrapper. The standalone helpers remain Lunora-native for the **non-auth** procedure case better-auth doesn't cover.
- **No binding/config needed**: confirmed `packages/config/src/wrangler-validator.ts` validates `durable_objects`/`migrations`/`tail_consumers` only; Turnstile has no Cloudflare binding (secret is a `.dev.vars`/secret env var). The plan touches **no** config/wrangler code — only document the `TURNSTILE_SECRET_KEY` secret.

## Item breakdown

Each item is its own PR.

- [x] **Item 1: `verifyTurnstile()` standalone helper.** New `packages/auth/src/turnstile.ts`. Pure async function `verifyTurnstile({ secret, token, remoteip?, fetch? = globalThis.fetch }): Promise<TurnstileVerifyResult>` that POSTs `application/x-www-form-urlencoded` (`secret`, `response`=token, optional `remoteip`) to `https://challenges.cloudflare.com/turnstile/v0/siteverify`, parses the JSON, and returns a typed `{ success: boolean; errorCodes: string[]; challengeTs?: string; hostname?: string; action?: string; cdata?: string }` (map snake_case `error-codes`/`challenge_ts` → camelCase). Inject `fetch` so it's unit-testable; never throw on a `success: false` verdict (return it). Throw only on transport failure / non-2xx with a structural `LunoraError`-shaped error so callers can distinguish "bot" from "siteverify down". Named exports only. Test (plain Node): a stub `fetch` returning `{ success: true }`, `{ success: false, "error-codes": ["invalid-input-response"] }`, and a 500 — assert the shape mapping and the throw-on-transport-fail branch.
- [x] **Item 2: `verifyTurnstileMiddleware()` procedure guard.** New `packages/auth/src/turnstile-middleware.ts`. A `Middleware<Context, Context>` (type-only `import type { Middleware } from "@lunora/server"`, mirroring `packages/ratelimit/src/middleware.ts:1`) built by `verifyTurnstileMiddleware({ secret, token, remoteip?, failOpen? })` where `token` and `remoteip` are `(ctx) => string | undefined` selectors (the procedure ctx has no raw headers — read the token from `args`/ctx, per `packages/auth/src/middleware.ts:244-249`). On `success: false` throw the structural `LunoraError` `{ name: "LunoraError", code: "FORBIDDEN", status: 403 }` (copy the throw shape from `ratelimit/src/middleware.ts:84-95`). On siteverify transport error fail **closed** by default (403) with `failOpen?: true` to admit — same default + escape hatch as ratelimit (`middleware.ts:43-56`). Named exports only. Test (plain Node): a stub `verifyTurnstile`/`fetch`; assert pass-through on success, throw `FORBIDDEN`/403 on failure, fail-closed on transport error, and `failOpen` admits.
- [~] **Item 3: `withTurnstile()` auth-handler wrapper — DROPPED (superseded by better-auth's `captcha` plugin).** Originally: new `packages/auth/src/turnstile-handler.ts`. `withTurnstile(inner: (request) => Promise<Response | undefined>, { secret, basePath?, segments?, getToken?, getRemoteIp?, failOpen? })` returns a `(request) => Promise<Response | undefined>` with the **same signature as `handleAuthRequest`** (`packages/auth/src/handler.ts:17`) so it drops in at the host call site or `WorkerOptions.authHandler` (`packages/runtime/src/create-worker.ts:468`). It only intercepts attempt routes — default `segments = ["/sign-up", "/sign-in"]` matched under `basePath` exactly like `isAuthAttemptPath` (`packages/runtime/src/create-worker.ts:833-843`; inline a local copy, do **not** import `@lunora/runtime`). For an attempt route it reads the token (default `getToken`: form field `cf-turnstile-response` or header `cf-turnstile-response`; **clone the request** before reading the body so `inner` still sees an unconsumed body), calls `verifyTurnstile`, and returns a `403` JSON `Response` on failure; otherwise delegates to `inner(request)`. Non-attempt routes pass straight through. Named exports only. Test (plain Node): fake `Request`s for `/api/auth/sign-up` (good token → delegates; bad token → 403) and `/api/auth/get-session` (always delegates, never verifies); assert the cloned body is still readable by `inner`.
- [x] **Item 4: barrel exports + `captcha` plugin re-export + `TURNSTILE_SECRET_KEY` secret docs.** Add `verifyTurnstile`, `verifyTurnstileMiddleware`, and the `TurnstileVerifyResult`/options types to `packages/auth/src/index.ts` (`:1-32`) — named exports, no default (no `withTurnstile`; that was dropped). Re-export better-auth's **`captcha`** plugin from `packages/auth/src/plugins.ts` (it has no `better-auth/plugins/<name>` subpath — import from the `better-auth/plugins` barrel). Document the `TURNSTILE_SECRET_KEY` secret in the auth setup docs (and note the `.dev.vars` grammar scaffolder in `@lunora/config` so `lunora dev` can prompt for it — but do **not** modify config code; a docs note is sufficient). Add a "CAPTCHA / Turnstile" section to the auth-plugins docs showing the `captcha` plugin for the auth flow and the standalone `verifyTurnstile()`/`verifyTurnstileMiddleware()` for non-auth procedures. ## STOP conditions

- Do **not** add a Cloudflare binding or touch `packages/config/src/wrangler-validator.ts`/`infer-bindings.ts` — Turnstile has no binding (verified: no `turnstile` kind exists there). If you find yourself editing config/wrangler code, STOP — the secret is a plain env var.
- If the procedure ctx genuinely cannot carry the Turnstile token in `args` for a given call site, the _procedure_ middleware (Item 2) is the wrong seam for that flow — prefer the auth-handler wrapper (Item 3), which has the real `Request`. Do not invent a way to smuggle raw `Headers` into the procedure ctx (the context deliberately omits them — `packages/auth/src/middleware.ts:244-249`); STOP and use Item 3 instead.
- In Item 3, if reading the token consumes the request body such that `inner(request)` (better-auth) then sees an empty body, the verification has broken auth — you **must** clone the request before reading. If you cannot guarantee `inner` sees an intact body, STOP and report.
- Keep every new test plain-Node with an injected `fetch`. Do **not** make a real network call to `challenges.cloudflare.com` in tests. If a test appears to need the live endpoint, STOP.
