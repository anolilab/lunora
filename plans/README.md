## Notes for executors

- `dist/` is gitignored and built on demand. Before running a package's
  `test`/`lint:types`, build dependencies once: `pnpm run build:packages` (or use
  `pnpm run test:affected` / `pnpm run lint:affected:types`). Skipping this
  produces misleading `X is not a function` / "missing export" errors. (This is
  itself the subject of plan 016.)
- The repo uses ESM with `moduleResolution: "bundler"` — **no `.js` extensions**
  in relative imports (the sole exception is `@cirrus/codegen`'s emitted output).
- Match each package's existing test style; do not introduce new test
  infrastructure.

## Findings considered and rejected

These surfaced during the audit but were dropped after vetting — recorded so they
aren't re-audited:

- **CLI/Vite "broken build, 19 failing tests" (missing `@cirrus/config`
  exports)** — FALSE POSITIVE. The audit ran filtered tests against a stale,
  gitignored `dist/`. The `detectAgentRules`/`AGENT_RULES_HINT` exports and
  `StudioHtmlConfig.rulesInstalled` all exist correctly in `packages/config/src`
  (added in HEAD `151a3eca`). Real residual captured as plan 016 (DX docs).
- **"Internal functions not enforced server-side" (server/runtime/mcp)** —
  REFUTED. The generated `handleRpc` enforces it at
  `packages/codegen/src/emit.ts:1745`
  (`visibility === "internal" && !isSystemDispatch()` → not found). The genuine
  residual (the test harness diverges) is captured as plan 004.
- **`do` subMemo cleanup "leak" on serialize failure
  (`shard-do.ts:2406-2430`)** — REJECTED. On serialize failure the code rolls
  back the in-memory unsubscribe and keeps the memo; sub-state and memo-state
  stay consistent. A "fix" that deletes the memo on rollback would _introduce_
  desync. Only a pathological repeated-serialize-failure scenario differs, not
  worth the risk. (This is why no plan 011 exists.)
- **Svelte `mutation()` recreates stores per call** — REJECTED. Creating fresh
  state per call matches React/Solid/Vue mutation hooks; `mutation()` is meant to
  be called once at component init. Calling it reactively is misuse, not a bug.
- **Mail: reject commas in Subject/header values** — REJECTED. Commas are valid
  and common in subject lines; rejecting them would break legitimate email.
  Address-field comma rejection (commas separate addresses) is correctly distinct
  and stays.
- **Weak/empty payment webhook secret = "complete bypass"** — DOWNGRADED, not
  planned. An empty/weak secret makes HMAC verification _fail_ all webhooks (the
  developer's own break), not an attacker bypass. A min-length assertion is a
  minor DX nicety; left out to keep the payment plan focused on the real ledger
  bugs (plan 006).
- **`?token=` in the WebSocket URL (do/runtime)** — BY-DESIGN, not planned. WS
  upgrades can't set `Authorization`; the code already documents this and
  recommends short-lived tokens. A larger ephemeral-WS-token design is a possible
  future hardening, not a bug fix.
- **"cursor race in bounded fan-out" (runtime/vectors)** — REJECTED. Benign on
  the single-threaded JS event loop (the reporting agents noted this themselves).
