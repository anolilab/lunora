## Backlog — vetted real, not planned this round

- **Binding feature parity**: `@cirrus/react` ships 22 modules
  (pagination, infinite query, presence, connection-status, auth gates,
  rate-limit, streams); vue/solid/svelte ship 7–8 (query/mutation/provider/
  hydrate only). The subscription core is already shared
  (`@cirrus/client/query`), so parity = extracting react's pagination/presence
  cores into `@cirrus/client` and writing thin adapters. M–L effort, needs a
  product decision on which hooks matter per framework.
- **God files**: `packages/do/src/shard-do.ts` (~4.3K lines),
  `packages/runtime/src/create-worker.ts` (~4.1K), `packages/do/src/ctx-db.ts`
  (~3.4K). Real maintainability cost, but decomposition is L-effort/HIGH-risk
  on the framework's hottest code; do it opportunistically per-domain (e.g.
  extract admin introspection from ShardDO first), not as a big-bang refactor.
- **Workerd integration coverage for OCC/transactions/migration claim**: the
  concurrency-sensitive primitives run only on `node:sqlite` in tests; the
  workerd suites (`__tests__/workerd/`) cover RPC/WS plumbing only. M effort;
  natural follow-up to plan 001.
- **Thin client workerd suite**: 3 integration tests vs an 1802-line
  mock-socket suite; the mock's synchronous `close()` can hide real-platform
  reconnect timing bugs. M effort.
- **`fake-sql.ts` drift hazard**: 4 test files still use the pattern-matching
  SQL fake (incl. a hand-maintained `changes()` mirror — the exact primitive
  OCC depends on); port them to the node-sqlite helper. S–M.
- **Studio `listTables` row counts**: `packages/do/src/introspect.ts:560-583`
  runs `COUNT(*)` per table on every table list — admin-only path, but slow on
  large shards. S effort (cached counts or approximate via `sqlite_stat`).
- **`CirrusClient.close()` listener hygiene**: `statusListeners` /
  `authTokenListeners` sets are not cleared on close (cirrus-client.ts:1518-1553).
  Only leaks if a closed client is retained; S effort, bundle into any client touch.
- **CLI empty catch blocks**: `admin-url.ts:21`, `detect-package-manager.ts:32`,
  `open-url.ts:79` — add debug-level logging. S.
- **CLI local-template copy is non-atomic**: `init/handler.ts:201-224` writes
  file-by-file with no staging; a mid-loop failure leaves a partial scaffold.
  Low harm on fresh dirs (the remote path already stages via temp dir); S–M to
  unify on the staging pattern.
- **CLI catalog hygiene**: `packages/cli/package.json` hard-pins 7 deps
  (`@visulima/*` alphas, `giget`, `@bomb.sh/tab`) outside pnpm catalogs,
  against the stated convention. May be deliberate (alpha pinning); confirm
  intent before mechanizing. S.
- **Small test gaps**: reconnect jitter boundaries tested via raw
  `Math.random` (reconnect.test.ts:40); no alarm-contract test for past
  `scheduledFor` arming an immediate fire (scheduler). Batch into the next
  touch of those suites. S.
- **WS upgrade origin policy**: when `CIRRUS_ALLOWED_ORIGINS` is unset, any
  origin is accepted (documented dev convenience in `shard-do.ts`). Auth is
  token-based (not ambient cookies), so CSWSH exposure is limited; consider a
  production warning when unset. Investigate-level.

## Direction findings (options for the maintainer, not ranked against bugs)

1. **Real `@cirrus/testing` (convex-test equivalent)** — the package is a
   16-LOC re-export of `@cirrus/mail/testing`. The architecture makes an
   in-memory backend cheap (ctx-db already runs on `node:sqlite` in the repo's
   own tests); a `createTestingContext()` + test client would let users
   unit-test queries/mutations without a DO. L effort; spike first.
2. **MCP admin tools** — `packages/mcp` exposes 5 read/run tools; ShardDO's
   admin RPC surface (migrations, export/import, writeRow, deleteRows,
   clearTable) is not exposed. Mapping them to MCP tools (admin-token-gated,
   audited) unlocks agent-driven seeding/exports. S–M effort; decide the
   confirmation model for destructive ops first.
3. **Advisor runtime rules** — 2 runtime lints vs 10 static; CLAUDE.md already
   promises "planned runtime rules over scan attribution". Function-to-scan
   attribution + aggregate-utilization rules would make Advisors actionable
   ("this query causes these scans"). M effort.
4. **Bulk admin ops asymmetry** — `deleteRows`/`clearTable` exist; no
   `bulkInsert`/`bulkUpdate`, so data loading is `writeRow`×N or full-shard
   import. M effort, low risk.
5. (Low confidence) **Sandboxes** — the last open VOID-TEARDOWN.md parity gap;
   labeled niche there. Scope demand before building.

## Findings considered and rejected

Recorded so the next audit doesn't re-litigate them. Each was checked against
the live code at `c865cfa6`:

- **"RPC `functionPath` unvalidated → TypeError"** — false; `parseEnvelope`
  validates it is a string (`create-worker.ts:1164`).
- **"Scheduler HMAC falls back to bearer = weak auth"** — by design; the
  fallback requires the admin token, which already grants strictly more power.
- **"Unbounded `topK.k` = DoS"** — `slice(0, k)` doesn't allocate beyond
  collected rows; `k = 0` returns empty (client error, not a vuln).
- **"CLI `isSafeSource` path traversal / allows http://"** — false;
  `includes("..")` catches all traversal forms and the prefix whitelist
  (`gh:`/`github:`/`https://`) never matches `http://`.
- **"Optimistic rollback clobbers newer pending value"** — false; both guards
  exist (`serverVersion` bump + `lastValue` identity, cirrus-client.ts:267-294).
- **"`pendingChangedTables` mutated during refresh iteration"** — false; the
  caller snapshots and clears before `refreshSubscriptions` (shard-do.ts:3936-3952).
- **"`handleStream().catch(()=>{})` swallows errors"** — by design;
  handleStream sends its own `type:"error"` frames, the catch guards only the
  dead-socket pre-try path (documented at the call site).
- **"Subscription results JSON.stringify'd twice per push"** — false; one
  stringify, reused for memo and wire frame (shard-do.ts:4103-4141).
- **"N identical subscriptions re-run N× per write"** — deliberate,
  documented trade-off; ReactiveCache is the designed remediation (comment
  block above `refreshSubscriptions`).
- **"useAuth registers a leaking listener per mount"** — false; one listener
  per client store (WeakMap), `useSyncExternalStore` unsubscribes per the
  React contract.
- **"Offline persistence failures silently swallowed"** — by design;
  `onPersistenceError` hook with `console.warn` last-resort fallback.
- **"Framework bindings re-implement subscription logic"** — false; all four
  import `createQuerySubscription` from `@cirrus/client/query`.
- **"FNV-1a fingerprint collision = auth risk"** — documented as
  change-detection only, not anti-spoofing; the real (reload) gap is plan 003.
- **"`@cloudflare/vite-plugin` exact pin blocks updates"** — the pin is
  actively managed with explicit bump criteria in `pnpm-workspace.yaml:111-121`;
  exemplary, not a finding.
- **"esbuild high CVE via vitest chain"** — dev-only transitive (vitest/vite),
  Deno-specific vector; noise floor per the audit playbook.
- **"`@cirrus/values` under-tested (4 test files / 1251 LOC)"** — false; the
  5 suites cover every public validator incl. Standard Schema conformance and
  type-level tests.
- **"Auth cookie flags not enforced by Cirrus"** — unverified speculation
  about better-auth's defaults; nothing concrete in `packages/auth` evidenced
  a gap.
- **"`readAttachment` lenient cast crashes on corrupt attachment"** — benign:
  attachments are written only by the DO itself, and a malformed `subs` value
  degrades to no-op iteration in `refreshSubscriptions`.
