## Why this matters

`@lunora/search-core` — the internal package whose analyzer/tokenizer decisions are frozen into every stored search index — is the only package in the platform/runtime cluster off the shared manifest conventions: it depends on `"@lunora/errors": "workspace:*"` while every sibling (`runtime`, `do`, `shard-engine`, `d1`, `sql-store`) pins `"1.0.0-alpha.22"`; it lacks the `fallow:audit` / `fallow:dead-code` / `fallow:health` scripts every sibling carries; and it declares `test:coverage` without the `@vitest/coverage-v8` devDependency, so the script cannot run. Divergence here means the package is excluded from the repo's dead-code/health gates and from the release tooling's version discipline.
