# Lunora Advisor — candidate SECURITY lint rules

A catalog of security footguns an **app developer** can hit through Lunora's DX, each a
candidate `@lunora/advisor` lint. Compiled from a source-verified audit of `packages/*`.
Every entry is confirmed reachable through the _current_ public API; the "secure-by-default"
list at the end records what was checked and is deliberately **not** a rule.

## How to read this

Each rule is tagged with an **implementation path**, which is the real cost driver (per the
codegen feeder — `@lunora/codegen`, ts-morph, ~30 `discover-*.ts` precedents feeding
`run-codegen.ts` → `advisor.ts` → `runAdvisor`):

- **[A] source-pattern** — new `discover-*.ts` + `LintContext` field + rule. Detects a
  call-site / builder-chain / schema shape (guard present-or-absent). ~30 precedents, cheap.
- **[B] config-evidence** — reads a config file (`wrangler.jsonc`) or a config _literal_
  (`lunora/auth.ts`, `defineBrowser({...})`). **No lint reads config today** — the first one
  builds a new `LintContext` channel (feeder `discoverWranglerConfig` + `wranglerConfig?` field
    - wiring); every later config rule then rides it for free.
- **[C] args→sink taint** — follow a user-supplied `args.*` value through locals into a
  dangerous sink. Feeders today are shape detectors, not taint. `discover-sql-interpolation.ts`
  (the `sql_injection_risk` feeder) is the closest model to extend. Materially more code;
  start narrow (single-hop: `args.x` used directly at the sink), don't build a general engine.

Severity uses the advisor's `Level`: **ERROR** (definite), **WARN** (likely), **INFO** (nudge).
Category is `SECURITY` throughout unless noted.

## Implementation status

**Shipped (45 rules, wired + typechecked + unit-tested + ESLint-clean across `@lunora/advisor`, `@lunora/codegen`, and `@lunora/config`)** — marked ✅ in the tables below:

Reusable codegen feeders back all but one (the config-evidence channel below), so later rules of the same shape are near-free:

- **`discover-config-calls.ts`** → `ConfigCallIR` / `AdvisorConfigCall` (`LintContext.configCalls`). Records, per factory/constructor call in `lunora/` (`createPayment`, `createInboundEmailHandler`, `RateLimiter`, `createBrowser`), whether its **config object literal** is statically analyzable and which keys are present / assigned literal `true`. Powers `payment_create_without_authorize`, `mail_inbound_dispatch_without_verify`, `ratelimit_default_memory_store`, `browser_allow_private_targets`. Add a callee to its two sets to feed the next config-literal rule.
- **`discover-procedure-middleware.ts`** (extended) → `ProcedureMiddlewareIR` / `AdvisorProcedureProtection` gained `fanOut`, `usesInsertManyUnsafe`, `unboundedAiGeneration` behaviour flags (body-walk booleans). Powers `privileged_fanout_from_public_procedure`, `insert_many_unsafe_user_data`, `ai_unbounded_generation_public`. Add another `isX(call)` detector + flag to feed the next handler-body rule.
- **`argument-taint.ts`** (shared module, **the Wave 3 taint primitive**) — extracted from the SSRF-fetch feeder so every argument-taint sink shares one implementation. Exports `referencesArgs` (textual `args`-value reference), `singleHopInitializer` (follows one `const x = args.y` binding), `isArgumentDerived` (the taint predicate: direct-or-single-hop `args` derivation), `isScopedByContext` (its `ctx` mirror: direct-or-single-hop `ctx` reference — an IDOR key that reaches `ctx`, even via a local `const`, is treated as server-scoped and not flagged), and `enclosingExportName`. `isArgumentDerived` + `isScopedByContext` are symmetric so the taint and scoping checks never disagree on a local-`const` key.
- **`discover-argument-derived-fetches.ts`** → `ArgumentDerivedFetchIR` / `AdvisorArgumentDerivedFetch` (`LintContext.argumentDerivedFetches`). **First Wave 3 taint feeder.** Records `ctx.fetch(url, …)` calls whose URL is `isArgumentDerived`. Powers `action_fetch_ssrf`.
- **`discover-owner-field-writes.ts`** → `OwnerFieldWriteIR` / `AdvisorOwnerFieldWrite` (`LintContext.ownerFieldWrites`). Records `ctx.db.{insert,replace,patch,insertManyUnsafe}` writes whose identity column (`userId`/`ownerId`/`tenantId`/… — a tight identity/tenancy allowlist) is `isArgumentDerived(value) && !isScopedByContext(value)`. Powers `owner_field_from_args_not_auth`.
- **`discover-storage-key-accesses.ts`** → `StorageKeyAccessIR` / `AdvisorStorageKeyAccess` (`LintContext.storageKeyAccesses`). Records `ctx.storage[.<bucket>].<method>(key, …)` calls (default + named bucket; key-taking read/write/URL/delete/multipart methods, `list`/`bucket` excluded) whose arg[0] key is arg-derived and unscoped. Powers `storage_key_from_user_args`.
- **`discover-kv-key-accesses.ts`** → `KvKeyAccessIR` / `AdvisorKvKeyAccess` (`LintContext.kvKeyAccesses`). Records `ctx.kv.{get,getRaw,getWithMetadata,put,delete}(key, …)` calls (`list` excluded — a prefix, not a key) whose arg[0] key is arg-derived and unscoped. Powers `kv_unscoped_user_key_idor`.
- **`discover-container-key-accesses.ts`** → `ContainerKeyAccessIR` / `AdvisorContainerKeyAccess` (`LintContext.containerKeyAccesses`). Records `ctx.containers.<name>.get(key, …)` calls whose instance-key arg[0] is arg-derived and unscoped (`.any()`/`.pool()` take no key, not sinks). Powers `container_instance_key_from_user_input`.
- **`discover-ai-raw-runs.ts`** → `AiRawRunIR` / `AdvisorAiRawRun` (`LintContext.aiRawRuns`). Records `ctx.ai.run(model, …)` calls whose **model** arg[0] is arg-derived and unscoped — `inputs` (arg[1]) is never inspected (feeding user data to a model is normal). Powers `ai_raw_run_escape_hatch`.
- **`discover-vector-namespace-accesses.ts`** → `VectorNamespaceAccessIR` / `AdvisorVectorNamespaceAccess` (`LintContext.vectorNamespaceAccesses`). Records `ctx.vectors.{query,upsert,upsertMany}(index, { namespace })` calls whose `namespace` property value is arg-derived and unscoped. Powers `vectors_namespace_from_user_input`.
- **`discover-mail-recipient-accesses.ts`** → `MailRecipientAccessIR` / `AdvisorMailRecipientAccess` (`LintContext.mailRecipientAccesses`). Records `ctx.mail`/`ctx.email` `{send,queue}({ to/cc/bcc })` calls whose recipient property value is arg-derived and unscoped (one finding per call, not per field). Powers `mail_recipient_from_request_input`.
- **`discover-browser-url-accesses.ts`** → `BrowserUrlAccessIR` / `AdvisorBrowserUrlAccess` (`LintContext.browserUrlAccesses`). Records `ctx.browser.{screenshot,pdf,content,scrape}(url, …)` calls whose navigation URL arg[0] is arg-derived and unscoped. Powers `browser_user_url_without_allowlist`, which **cross-references** the existing `configCalls` evidence and suppresses findings when an analyzable `createBrowser` is hardened with `allowedHosts` or `resolveDns` — the first taint rule to combine an `args.*`→sink signal with config-call hardening evidence.
- **`discover-storage-uploads.ts`** → `StorageUploadIR` / `AdvisorStorageUpload` (`LintContext.storageUploads`). Records each `ctx.storage[.<bucket>].<method>` upload/URL-signing call (`upload`/`store` options at arg index 2; `generateUploadUrl`/`getPresignedUrl`/`getSignedUrl` options at arg index 1), capturing whether the options literal is statically analyzable, which keys are present, and any statically-known `expiresInSeconds` literal. Powers `storage_upload_without_content_type_allowlist`, `storage_upload_without_max_size`, `storage_generate_upload_url_no_content_type_pin`, `storage_presigned_url_for_private_content` — a config-presence check keyed on the method's own options position.
- **`discover-privileged-dispatches.ts`** → `PrivilegedDispatchIR` / `AdvisorPrivilegedDispatch` (`LintContext.privilegedDispatches`). **First feeder to taint a non-`args` root.** Detects `defineQueue` / `defineWorkflow` handlers (matched by callee name) and records each `ctx.run`/`context.run`/`.run{Query,Mutation,Action}` dispatch whose args reference the handler's untrusted _payload_ — `context.params` for a workflow, a `for (… of batch.messages)` body for a queue — with one local `const`/destructuring hop, resolving the `api.<file>.<export>` target. Powers `privileged_dispatch_unvalidated_payload`, whose lint **cross-references** `rlsProcedures` and fires **only** when the dispatched target has `usesRls: true` (a system-identity dispatch genuinely bypasses that target's row policy) — so a queue/workflow that dispatches into a self-validating, non-RLS function (the common, correct case — e.g. the playground's own welcome-message workflow) is never flagged.
- **`discover-http-action-guards.ts`** → `HttpActionGuardIR` / `AdvisorHttpActionGuard` (`LintContext.httpActionGuards`). Records each `httpAction`/`httpRoute` handler, whether its body performs a side effect (`ctx.runMutation`/`runAction` or a `ctx.db` write) and whether it ever reads `ctx.auth`/`ctx.auth.userId`. Powers `http_action_missing_auth_guard` (side-effecting + never reads auth → unauthenticated write path). Distinct from `admin_route_without_guard` (Studio routes).
- **`discover-fail-open-guards.ts`** → `FailOpenGuardIR` / `AdvisorFailOpenGuard` (`LintContext.failOpenGuards`). Records `rateLimit(...)` / `verifyTurnstileMiddleware(...)` middleware whose options literal sets `failOpen: true`, plus whether the guarded procedure name is sensitive (signin/signup/reset/OTP/payment). Powers `ratelimit_middleware_fail_open`.
- **`discover-flag-security-defaults.ts`** → `FlagSecurityDefaultIR` / `AdvisorFlagSecurityDefault` (`LintContext.flagSecurityDefaults`). Records `ctx.flags.boolean(key, default)` reads whose result gates an authorization/early-return branch, capturing the fallback `default` literal and whether `key` is security-shaped (auth/admin/rls/lockdown/gate/enforce/allow). Powers `flag_gates_security_with_unsafe_default` (a provider-outage `default` selecting the permissive branch).
- **`discover-identity-claim-reads.ts`** → `IdentityClaimReadIR` / `AdvisorIdentityClaimRead` (`LintContext.identityClaimReads`). Records `ctx.auth.identity.<key>` reads in authorization positions and cross-references the `defineIdentity({...})` declared-claim set; a read of an **undeclared** claim is unvalidated/forgeable. Powers `identity_undeclared_claim_trusted`.
- **`discover-payment-webhooks.ts`** → `PaymentWebhookIR` / `AdvisorPaymentWebhook` (`LintContext.paymentWebhooks`). Records `createPayment`/webhook config literals carrying a statically-known `webhookToleranceSeconds`, flagging implausibly large values (no upper ceiling). Powers `payment_webhook_wide_tolerance` — **narrowed** from the catalog's `payment_webhook_unverified_or_wide_tolerance`: only the wide-tolerance half ships (the "unverified route" half is FP-prone — signature verify is otherwise fail-closed).
- **`discover-ai-tool-side-effects.ts`** → `AiToolSideEffectIR` / `AdvisorAiToolSideEffect` (`LintContext.aiToolSideEffects`). Records `generateText`/`streamText` calls that pass user-derived messages **and** supply a `tool({ execute })` whose body performs a mutation / `ctx.run` / external send. Powers `ai_tool_side_effect_prompt_injection` (prompt-injection driving a privileged side effect). Heuristic.
- **`discover-soft-delete-reads.ts`** → `SoftDeleteReadIR` / `AdvisorSoftDeleteRead` (`LintContext.softDeleteReads`). Records reads of a soft-delete table where `includeDeleted` is set from `args.*` or hardcoded `true` on a `.public()` read. Powers `soft_delete_include_deleted_from_args` (resurfaces tombstoned rows — a read scope, not access control). Reads the schema's `softDelete` metadata (surfaced via `AdvisorTable.softDelete` / `fromServerSchema`).
- **`discover-relation-loads.ts`** → `RelationLoadIR` / `AdvisorRelationLoad` (`LintContext.relationLoads`). Records `with: { <rel> }` relation loads on a parent read where `<rel>` resolves to a masked / `rls`-required table surfaced through an unprotected parent. Powers `masked_relation_leak_via_with` (nested relations are not masked/filtered).
- **`config/wrangler-secret-variables.ts`** → `WranglerVariableIR` / `AdvisorWranglerVariable` (`LintContext.wranglerVariables`). **The one non-codegen feeder — a new config-evidence channel.** Lives in `@lunora/config` (the only layer that reads `wrangler.jsonc`); `codegen` can't host it because `config → codegen` already, and the reverse edge would be a cycle. `codegen` factors its secret matchers into `secret-rules.ts` (`redact` / `secretKindOf`, re-exported from the package root) so `config` reuses the **exact** `hardcoded_secret` shape heuristics without duplicating them, then adds a secret-suggestive key-name rule (word-token `SECRET`/`PASSWORD`/`TOKEN`/`DSN`/… plus `*_KEY` compounds, bare `KEY` excluded) gated on a min value length, skipping placeholders and public/publishable keys. The raw value never leaves `config` — only a `redact()`ed preview crosses into the IR. `@lunora/cli` (`lunora codegen`) and `@lunora/vite` collect it and pass `runCodegen({ wranglerVariables })`, which forwards it to `lintSchema`. Powers `plaintext_secret_in_wrangler_vars`.

**Shipped as of the latest change: the Family-A trio** (rules that needed brand-new analysis primitives, each with its own feeder + `LintContext` channel; typechecked + unit-tested + ESLint-clean across `@lunora/advisor` and `@lunora/codegen`):

- **`discover-http-header-writes.ts`** → `HttpHeaderWriteIR` / `AdvisorHttpHeaderWrite` (`LintContext.httpHeaderWrites`). A **new request-input taint root** — an `httpAction` handler takes a `Request` (its second positional param), not `args`, so the existing `args.*` helpers didn't reach the header value. Records response-header writes (`headers.set`/`append`, `new Response(…, { headers })`, `new Headers({…})`) whose value is derived from that raw request param with no CRLF sanitizer. Powers `http_action_response_header_injection`. **Scope:** `httpAction` only — the `httpRoute` options-object form (`({ ctx, request }) => …`, request as a destructured property) is not yet covered; that's a fail-safe under-report (a header injection there is silently unflagged), a future extension, not a claim.
- **`discover-raw-row-returns.ts`** → `RawRowReturnIR` / `AdvisorRawRowReturn` (`LintContext.rawRowReturns`). **Return-shape analysis** — records a `query` that returns raw table rows (`get`/`findMany`/`findFirst`/fluent `.collect()`, through one const hop) and whether the builder chain carries `.output(...)` or a `mask(...)` step. Powers `output_projection_missing_on_public_read` (public visibility + no projection + PII-named columns).
- **`discover-normalize-id-authorization.ts`** → `NormalizeIdAuthorizationIR` / `AdvisorNormalizeIdAuthorization` (`LintContext.normalizeIdAuthorizations`). **Negative proof** — records a `query`/`mutation` that null-gates a `ctx.db.normalizeId(table, id)` result reaching an id-first `get`/`patch`/`delete` sink, plus whether the chain carries `.use(rls(...))` and whether the handler mentions any ownership/identity signal. Powers `normalize_id_used_as_authorization`, biased hard toward silence (public-only, no RLS coverage, no ownership mention).

**Declined:** `dynamic_function_reference` (Wave 3 [C]) — maintainer decided **not** to ship. Even the narrowed low-FP subset (computed-bracket + arg-derived refs) is rare enough in real code that the rule isn't worth its maintenance surface; bare-identifier `api.*`/`internal.*` refs are the common legitimate case. Left unbuilt by design.

**Not yet built (~5, all Wave 4):** the rules marked **⛔ deferred** below (each held with a recorded infeasibility verdict). Each needs evidence that lives **outside** the app's `lunora/` source (host/env/CLI config), so it's best delivered as a setup/docs advisory rather than a codegen lint. The three Family-A rules that needed new analysis primitives (`http_action_response_header_injection`, `output_projection_missing_on_public_read`, `normalize_id_used_as_authorization`) have now shipped — see below.

**⛔ Deferred with a recorded infeasibility verdict** (evaluated, then held — not silently skipped). Marked ⛔ in the tables below:

- **Wave 4 — evidence outside `lunora/`** (5 rules, best delivered as setup/docs advisories rather than codegen lints, since the feeder only sees the app's `lunora/` source): `flag_value_exposes_secret_to_client` (needs client-hook ∩ env-provider cross-ref across packages), `container_bridge_admin_token`, `mcp_admin_token_over_least_privilege`, `admin_ws_token_in_query_param`, `run_command_no_prod_guard` (all read the host/env/CLI config, not `lunora/`).

**Formerly deferred, now shipped (Family A — needed new analysis primitives):**

- `http_action_response_header_injection` (Wave 3) — needed a **new taint root**: an `httpAction` handler takes a `Request`, not `args`. Shipped via `discover-http-header-writes.ts`, a request-input taint pass over `httpAction` header writes (the `httpRoute` destructured-request form is a fail-safe under-report, not yet covered).
- `output_projection_missing_on_public_read` (Wave 1) — needed **return-shape analysis** (raw table rows vs. a projection). Shipped via `discover-raw-row-returns.ts`, gated on `.public()` visibility, absence of `.output(...)`/mask, and PII-named columns to hold the FP rate under the advisor's bar.
- `normalize_id_used_as_authorization` (Wave 3) — needed **negative proof** (that _no_ intervening ownership predicate or RLS covers the id between validate and use). Shipped via `discover-normalize-id-authorization.ts`, biased hard toward silence (public-only, no `.use(rls(...))`, no ownership/identity mention, no schema-required RLS coverage).

**Resolved design decision — `dynamic_function_reference` (DECLINED, not shipped):** the catalog spec (below) would flag a `ctx.run{Query,Mutation,Action}` reference that is "a variable". But a survey of real usage shows bare-identifier refs (`ctx.runMutation(internalSend)`, `ctx.runAction(processWebhook)`, `ctx.runQuery(ref)`) and string-literal paths (`ctx.runQuery("users:get")`) are common and legitimate — a variable almost always holds a _static_ `api.*`/`internal.*` reference. Flagging every variable at ERROR level would be a false-positive storm. The only low-FP subset was **computed bracket access** (`api[expr]`/`internal[expr]` with a non-literal index) + **arg-derived refs** (reusing the taint helper). **Maintainer decision: do not ship** — that subset is too rare in real code to justify the rule's maintenance surface. Left unbuilt by design.

## Verified secure-by-default — deliberately NOT rules

Checked and found already hardened; do not spend a rule here.

- **Admin plane fail-closed** — `checkAdminAuth` returns `false` when no token is configured; all
  `/_lunora/admin/*` + `/_lunora/migrate` 403; constant-time compare. runtime/create-worker.ts:1395
- **Studio is dev-only** — `apply:"serve"`, loopback + DNS-rebind Host check + CSRF; not in prod builds. vite/studio-plugin.ts:426
- **No error-response leakage** — `toErrorResponse` never echoes `error.message`; returns generic `INTERNAL`. runtime/errors.ts:79-90
- **`.dev.vars`** — written `0o600`, `.example` is placeholders, `.gitignore` covers `.dev.vars*`. config/scaffold-dev-variables.ts
- **Destructive CLI guarded** — deploy/reset/migrate/seed all gate on `--yes`/TTY/explicit `--url`+admin token.
- **Seed → prod GUARDED** — `confirmRemoteSeedTarget` refuses non-local without `--yes`/TTY; `--reset` blocked remote; `isLocalUrl` fails safe. cli/commands/seed/handler.ts:182-205
- **MCP write-gating** — `allowWrites` defaults **false**; write tools omitted from ListTools and refused at dispatch; `assertRunnable` allowlists discovered public fns + enforces kind. mcp/tools.ts
- **Scheduler DO** — `originUrl` from env not request body (anti-SSRF); `scheduledFor` bounded; HMAC/admin dispatch auth. scheduler/scheduler-do.ts:424,460-476
- **Shard/fan-out** — runtime fails **closed** without `authorizeShard`; `validateFanOut` edge-validates the merge spec. runtime/create-worker.ts:1141-1177,1569
- **Mail header injection** — CR/LF/comma injection blocked in address parsing. mail/address.ts:23-39
- **Payment webhook signature** — fail-closed; adapter requires a non-empty `webhookSecret`. payment/webhook.ts:99-100,146-148
- **Vectors / KV / storage key validation** — topK/batch bounded; traversal/NUL/length blocked. (Only the _tenancy_ scoping gaps above remain.)
- **Client optimistic/offline queue** — the DO re-validates identity + client-seq server-side; not app-code lintable.
