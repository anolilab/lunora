`@lunora/auth` is a Cloudflare-native auth module. It is **not** better-auth
running on Workers; the wire shape is borrowed but the storage and crypto
are first-party so it boots without external services.

```ts
import { createAuth, providers } from "@lunora/auth";

export const auth = createAuth({
    secret: env.AUTH_SECRET,
    providers: [
        providers.emailPassword(),
        providers.github({ clientId: env.GH_CLIENT_ID, clientSecret: env.GH_CLIENT_SECRET }),
        providers.google({ clientId: env.G_CLIENT_ID, clientSecret: env.G_CLIENT_SECRET }),
    ],
});
```

## Mount the routes

```ts
import { createWorker } from "lunora/runtime";

export default createWorker({
    shardDO: env.SHARD,
    routes: auth.routes(),
});
```

`auth.routes()` returns `{ "/auth/signup": handler, "/auth/signin": handler, ... }`.
You can prefix-mount or merge with your own routes.

## Read `ctx.auth` in functions

`auth.resolveAuth(request, env)` resolves the session cookie and populates
`ctx.auth` for every `query` / `mutation` / `action`. When unauthenticated
`ctx.auth = { authenticated: false, user: null, session: null }`.

## Sessions

Sessions live in a dedicated Durable Object — `SessionDO` from `@lunora/do`.
The auth package writes through the `SESSION` namespace binding and shards
sessions across DO instances using the first 16 characters of each token
(`idFromName(token.slice(0, 16))`). Same-prefix tokens co-locate; one DO
never has to own every session at once.

```jsonc
// wrangler.jsonc
{
    "durable_objects": {
        "bindings": [
            { "name": "SHARD", "class_name": "ShardDO" },
            { "name": "SESSION", "class_name": "SessionDO" },
        ],
    },
    "migrations": [{ "tag": "v1", "new_sqlite_classes": ["ShardDO", "SessionDO"] }],
}
```

Tokens are 256-bit base64url random strings (~43 chars), generated by
`crypto.getRandomValues` and stored only under `s:${token}` inside the DO's
KV. Default TTL is 7 days (`sessionTtlSeconds`). User records — email,
password hash, provider linkage — stay in D1; only session lifecycle moved
to the DO.

## OAuth providers

OAuth is handled by **better-auth** — social providers run through its
built-in social-provider flow, and any additional providers go through
`genericOAuth`. Lunora does not implement its own code/token/userinfo
exchange or `id_token` verification; it configures better-auth and forwards
the request. The GitHub and Google providers each perform a real
code-for-token-for-userinfo exchange:

- **GitHub** — `POST github.com/login/oauth/access_token` with PKCE
  `code_verifier`, then `GET api.github.com/user`. If the user keeps their
  primary email private, the package falls back to `GET /user/emails` and
  picks the primary verified entry.
- **Google** — exchanges the authorization code for tokens and reads the
  returned `id_token` (JWT) for `sub`, `email`, `name`. The `id_token`
  signature is **verified against Google's JWKS** as part of better-auth's
  social-provider flow — Lunora does not roll its own OAuth or trust the
  transport alone.

Configure credentials via `OAUTH_GITHUB_CLIENT_ID`, `OAUTH_GITHUB_CLIENT_SECRET`,
`OAUTH_GOOGLE_CLIENT_ID`, `OAUTH_GOOGLE_CLIENT_SECRET` (or pass them to
`providers.github({...})` directly). If both env and provider options leave
the credentials empty, the callback route returns `503 OAUTH_NOT_CONFIGURED`
instead of falling back to a stub user.

## Rate limiting

`/api/auth/*` is **rate-limited by default**. better-auth enables rate
limiting automatically, but only when `NODE_ENV === "production"` — a check
that is unreliable on Cloudflare Workers, where there is no Node
`process.env` at request time. So `createAuth` defaults `rateLimit.enabled`
to `true` whenever you don't set it explicitly, ensuring auth endpoints are
throttled on real deployments (and in dev) rather than silently wide open.

The defaults are better-auth's: a 10-second window with a max of 100
requests per IP, plus stricter per-path rules for sensitive endpoints
(sign-in, sign-up, etc.). Configure it through the `rateLimit` option, which
is forwarded to better-auth verbatim:

```ts
export const auth = createAuth({
    secret: env.AUTH_SECRET,
    rateLimit: {
        window: 60, // seconds
        max: 100, // requests per window per IP
        customRules: {
            "/sign-in/email": { window: 10, max: 5 },
        },
    },
});
```

To turn rate limiting off — for example when you front auth with your own
limiter (see [`@lunora/ratelimit`](/docs/packages/ratelimit)) — pass an
explicit flag; an explicit `enabled` value always wins over the default:

```ts
export const auth = createAuth({
    secret: env.AUTH_SECRET,
    rateLimit: { enabled: false },
});
```

## Password hashing

`hashPassword` / `verifyPassword` are PBKDF2-SHA-256 with 600 000 iterations
(OWASP 2023 baseline). They run in WebCrypto, so no Node polyfills are
needed on Workers.
