`@lunora/platform-rivet` is the Rivet **host**: the `@lunora/platform` contracts
— `ShardHost`, `SocketHost`, `ShardDirectory`, `ShardKvStore`, `SchedulerHost` —
implemented over [Rivet Actors](https://rivet.dev/actors) and the `rivetkit`
runtime.

```ts
import { createRivetPlatform } from "@lunora/platform-rivet";

// Once per actor wake, from `createVars`.
const platform = await createRivetPlatform(c, { onAlarm, onDispatch });
```

## Why a third host looks different from the second

A Rivet Actor is the closest primitive to a Durable Object outside Cloudflare:
one addressable, single-writer instance per key, with its own SQLite database,
its own durable schedules, and a sleep/wake lifecycle rather than an
eviction-and-rehydrate one. Several rows below therefore read `native` where
`@lunora/platform-node`'s read `emulated` — sharded state, alarms, hibernated
sockets and the scheduler are things the platform genuinely provides here, not
things Lunora rebuilds out of `setTimeout` and a table. This host is also the
first to get `SchedulerHost.cron` — runtime cron registration — from the
platform rather than from its own bookkeeping.

## The one structural mismatch

`ShardSqlExec.exec` is **synchronous**; every Rivet SQLite entry point is a
promise, because the actor reaches its database through the runtime. The
contract anticipates this ("async-backed with a sync facade"), and this package
is that facade: a `better-sqlite3` working copy in the actor's memory answers
every read, and the whole database is serialized back into Rivet's SQLite at
each commit. Correct, bounded by what one actor can hold, and O(database size)
per committed write — a small-shard strategy, which is what `.shardBy()` is for.

## Status

**Experimental, and narrower than the Node host.** There is no `lunora dev
--target rivet`, no deploy driver, and no `.global()` table backend. The
contracts pass `@lunora/platform`'s conformance TCK, but against an in-memory
Rivet actor double rather than a live engine — see
[`plans/rivet-host-findings.md`](https://github.com/anolilab/lunora/blob/alpha/plans/rivet-host-findings.md)
for what that leaves open.

Its API snapshot is gated at the **experimental** tier
(`scripts/api-snapshot.js`): here is a public-API change and must be reviewed as
one. This package is Experimental — the snapshot records how its surface moves,
and carries **no SemVer promise until the package graduates**
(`ROADMAP.md`'s [graduation bar](https://github.com/anolilab/lunora/blob/alpha/ROADMAP.md#experimental--stable-the-graduation-bar)).
`scripts/check-roadmap-tiers.js` fails the install if the roadmap and the
snapshot tier ever disagree.

Read the table below as an honest self-rating, not an invitation to run
production traffic on it.

## Wiring

Rivet delivers schedules by invoking an **action on the actor**, so three
one-line handlers have to exist on the actor definition. The action names are
exported constants, because a typo there is an alarm that silently never
arrives.

```ts
import { actor, setup } from "rivetkit";
import { db } from "rivetkit/db";
import { RIVET_ALARM_ACTION, RIVET_CRON_ACTION, RIVET_SCHEDULER_ACTION, createRivetPlatform } from "@lunora/platform-rivet";

export const shard = actor({
    db: db({ onMigrate: async () => {} }),
    options: { canHibernateWebSocket: true },
    createVars: async (c) => ({ platform: await createRivetPlatform(c, { onAlarm, onDispatch }) }),
    onWebSocket: (c, ws) => {
        c.vars.platform.sockets.accept(ws);
    },
    onSleep: async (c) => c.vars.platform.close(),
    actions: {
        [RIVET_ALARM_ACTION]: async (c) => c.vars.platform.deliverAlarm(),
        [RIVET_SCHEDULER_ACTION]: async (c, id: string) => c.vars.platform.deliverScheduledJob(id),
        [RIVET_CRON_ACTION]: async (c, path: string, args: string) => c.vars.platform.deliverCronTick(path, JSON.parse(args)),
    },
});
```

The shard directory lives outside the actor, on a RivetKit client:

```ts
import { createClient } from "rivetkit/client";
import { createRivetShardDirectory } from "@lunora/platform-rivet";

const client = createClient<typeof registry>("http://localhost:6420");
const directory = createRivetShardDirectory(client.shard, {
    resolveRegion: (hint) => ({ apac: "sin", enam: "atl", weur: "fra" })[hint],
});
```

`c.db` is **required**: an actor declared without `db: db({ … })` type-checks
and then loses every write on sleep, because the shard's durable state is that
SQLite database.
