# apps/docs

The Lunora documentation & marketing site (`@lunora/docs`) — TanStack Start on
Vite, file-based routing via TanStack Router, Fumadocs/MDX content, Tailwind v4
with shadcn/ui, prerendered to static HTML.

> Deployed as a Cloudflare Worker (`wrangler.jsonc`, `@cloudflare/vite-plugin`). The Worker cannot compile wasm from bytes at runtime, so `/api/og` does not render under workerd yet (satori's harfbuzz), and `/code-of-conduct` is not prerendered and returns 500 live. Verify a change with `pnpm run build` then `wrangler dev -c dist/server/wrangler.json`.

Writing rules for every docs page (voice, page types, code samples, agent
readability): [`STYLE.md`](STYLE.md).

## Do not hand-edit

- `src/routeTree.gen.ts` — generated by TanStack Router.
- `src/content/docs/packages/**` — gitignored, collected from each package's own `docs/` folder.
- `src/data/packages.ts`, `src/data/stats.json` — generated at build time.

**Docs live next to the code.** A package's pages are authored in
`packages/<name>/docs/index.mdx` (plus optional extra pages and a `meta.json`
for ordering). Packages are flat — `packages/<name>`, scope `@lunora/*` — with
no category sub-folders.

## Commands

```bash
pnpm dev               # generate-packages + copy-docs, then the dev server
pnpm build             # + check-doc-imports + fetch-stats + vite build
pnpm lint:doc-imports  # code samples in docs import real, exported symbols
pnpm lint:types        # fumadocs-mdx codegen, then tsc --noEmit
```

Build-time scripts, in order — `scripts/generate-packages.js` (discovers
workspace packages via `project.json` `category:*` tags, merges
`src/data/packages-metadata.json`) → `scripts/copy-package-docs.js` (collects
`packages/*/docs/`, sanitises MDX, builds a categorised `packages/meta.json`) →
`scripts/check-doc-imports.mjs` (fails the build on a code sample importing a
symbol nothing exports; not run in `dev`) → `scripts/fetch-stats.js`
(network-bound; skipped by `dev`).

## Adding a package to the site

1. Create `packages/<name>/docs/index.mdx`.
2. Add a `category:<slug>` tag to the package's `project.json`. Valid slugs are the keys of `CATEGORY_TITLES` in `scripts/package-categories.js` — a new slug needs an entry there **and** in `CATEGORY_COLORS`, which is keyed by display title, not slug.
3. Optionally add `displayName` / `description` / `features` to `src/data/packages-metadata.json`.

## Dev-only tools

`vite.config.ts` loads `@visulima/dev-toolbar` and `@visulima/vite-overlay`
through a `tryRequire` guard in development. They are deliberately **not**
declared dependencies — they no-op unless present in the workspace, so don't
"fix" the missing entries in `package.json`.
